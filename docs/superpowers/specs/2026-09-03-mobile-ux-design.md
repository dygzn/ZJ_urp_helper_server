# URP 教务助手前端体验收口设计

## 背景

URP 教务助手是一个原生 JavaScript SPA，包含首页、课程表、考试安排、成绩、教学评估、公告、反馈、会员、快捷指令 API 与服务展示等页面，并另有管理员后台和学生优惠活动详情页。当前前端经历了多次页面级追加样式，桌面端基本可用，但移动端存在触控热区过小、头部信息拥挤、弹窗行为不一致、访客状态覆盖页面内容、错误反馈不具备恢复路径等问题。

本次设计以真实手机使用为主，目标是降低误触和认知负担，同时不改变现有后端接口、数据结构、会员规则、教务查询逻辑或广告业务行为。

## 已确认的基线问题

在本地 Flask 服务的 390×844 视口中观察到：

- 侧边栏关闭按钮约 19×27px，菜单按钮约 36×32px；
- 广告选项与广告关闭按钮均约 24×24px，紧急事项刷新按钮约 34×34px；
- 侧边栏导航项高度约 39px，低于稳定的手机触控目标；
- 页面 viewport 禁用了缩放；
- `templates/index.html` 中微信联系入口的 class 名含有断开的空格，导致该入口失去统一样式；
- 访客切换到课程表、考试、成绩或评估页时，`loadPageData()` 会直接用绑定提示覆盖原页面 DOM，登录后无法可靠恢复原页面；
- 用户端多处使用原生 `alert()` / `confirm()`，反馈方式阻塞且不一致；
- 加载错误通常只有静态“加载失败”文字，缺少重试动作；
- 菜单和弹窗没有统一的 Esc、焦点回收、滚动锁定与遮罩状态管理。

## 目标与非目标

### 目标

1. 所有可操作控件在手机端拥有不小于 44px 的可点击热区，视觉图标可以小于 44px，但热区不能小于 44px。
2. 手机端首屏头部在 390px、414px 宽度下不横向溢出，菜单、标题、登录状态和广告各自有稳定布局。
3. 侧边栏、弹窗、联系方式气泡和页面切换拥有一致的打开、关闭、焦点与键盘行为。
4. 访客进入受限页面时保留原页面 DOM，登录成功后能恢复用户原先想访问的页面并触发正确数据加载。
5. 关键异步操作给出进行中、成功、失败和重试状态，不依赖浏览器原生弹窗显示普通结果。
6. 课程表、成绩、反馈、会员、快捷指令 API、服务页、广告详情页和管理员端在窄屏下保持可读、可操作。
7. 保留工作区中已有的广告转化相关业务改动，不覆盖或回滚与本设计无关的用户修改。

### 非目标

- 不修改 Flask 路由、数据库 schema、支付接口、会员价格、教务抓取逻辑或广告统计口径。
- 不把现有 SPA 一次性迁移到 React/Vue 等框架。
- 不重写所有页面文案；只调整会造成误解、重复或操作不清晰的交互提示。

## 设计方案

### 1. 体验基础层

在 `static/css/style.css` 与 `static/css/admin.css` 中建立统一的交互尺寸与状态规则：

- 去除 `maximum-scale` 与 `user-scalable=no`，保留浏览器缩放能力；
- 菜单、关闭、刷新、广告操作、图标按钮、导航项、表单控件和主要按钮统一设置手机端最小 44px 热区；
- 加强 `:focus-visible`、禁用态、按下态和高对比边界；
- 为头部、侧边栏、底部固定操作区和弹窗加入 `env(safe-area-inset-*)` 兼容；
- 删除依赖 `touchend.preventDefault()` 的全局双击拦截，避免阻断缩放和原生触摸行为；
- 将极小的 10–11px 辅助文字限制在非关键装饰场景，关键提示使用至少 12–14px。

### 2. 导航与页面状态

在 `templates/index.html` 增加明确的 `aria-label`、`aria-current` 和页面访问提示容器。新增 `static/js/ui-ux.js` 作为无框架的体验辅助层，提供纯函数和轻量 DOM 辅助能力：

- `normalizePageName(pageName, availablePages, fallback)`：对 URL、本地存储和点击来源统一页面名；
- `getGuestAccessCopy(pageName)`：生成受限页面的标题、说明和绑定按钮文案；
- `isDismissibleModal(modal)`：区分登录弹窗与普通可关闭弹窗；
- `getFocusableElements(container)`：为弹窗焦点管理提供可操作元素集合。

`main.js` 保留现有页面函数作为业务入口，但将访客限制改为给页面加锁定状态并显示独立的访问提示，不再覆盖原始页面内容。登录成功后恢复锁定页面并调用 `switchPage()`，确保课程表、成绩等页面重新渲染。

侧边栏打开时锁定背景滚动；点击遮罩、按 Esc 或选择导航项关闭侧边栏；关闭后将焦点还给菜单按钮。

### 3. 弹窗与反馈

用户端增加统一的弹窗基础行为：

- 打开时保存触发源焦点，关闭时回收焦点；
- 普通弹窗支持 Esc 和点击背景关闭，登录弹窗仍需显式关闭或选择访客，避免误丢失登录流程；
- 同一时刻只保留一个遮罩状态，避免不同函数分别操作 `display` 和 `.active` 导致状态不同步；
- 弹窗内容区使用 `max-height` 与内部滚动，手机端改为接近底部抽屉式的可读宽度。

新增轻量 Toast，用于替代普通成功、失败和提示类 `alert()`；需要用户确认的换绑和密钥重生成仍使用统一确认弹窗。错误内容尽可能就地显示，并附“重试”按钮。

### 4. 页面级移动端改造

- **首页**：头部采用“菜单/标题/状态 + 广告”两行布局；广告操作按钮扩大热区；紧急事项刷新按钮不再压缩到 34px。
- **课程表**：保持周末按需隐藏的现有逻辑；将周次切换、刷新、更新和历年查询分为清晰的操作组，手机端按钮至少 44px 并避免连续多个按钮产生误触。
- **成绩与考试**：入口卡片保持两列但保证每张卡片的文字可读；选择学期与考试的弹窗使用统一关闭、滚动和焦点行为。
- **反馈**：公开/私密选项扩大为整块可点击标签；提交过程显示进行中态，失败时保留已填写内容并提供重试。
- **会员与快捷指令 API**：套餐和支付方式使用明确的单列移动布局；复制密钥与重生成操作增加状态反馈和确认说明。
- **找我做事**：修复联系方式入口样式错误；联系方式气泡中的每个选项保持完整热区，并支持 Esc、点击外部关闭。
- **广告详情页**：返回链接、复制卡片和底部 CTA 采用一致的触控尺寸，确保固定 CTA 不遮挡正文和安全区。
- **管理员端**：将 Tab、刷新、表单控件、确认弹窗和表格容器统一到同一触控规则；宽表在窄屏使用明确的横向滚动容器，不压缩到无法阅读。

## 错误处理与兼容性

- 所有新 UI 辅助函数在 `window.URPUI` 上暴露，在 Node 测试环境以 CommonJS 导出，避免引入构建工具。
- 浏览器不支持 Clipboard API 时沿用现有 textarea 回退方案。
- `localStorage`、`sessionStorage`、History API 不可用时继续完成主要操作，不因体验增强导致登录或查询失败。
- `prefers-reduced-motion: reduce` 下不使用页面位移和强调动画。
- 不改变后端返回字段；当接口返回异常或非 JSON 时，前端显示可理解的通用错误并保留重试入口。

## 验收标准

### 自动化与静态验证

- 新增 UI 辅助层的 Node 单元测试，覆盖页面名规范化、访客提示、弹窗可关闭性与焦点元素筛选；每项测试先观察失败，再实现通过。
- 现有 `tests/*.js` 全部通过；执行 `git diff --check` 无空白错误。
- 前端脚本可被 Node 解析，浏览器加载不产生新的未处理异常。

### 浏览器验证

在本地服务中使用 Playwright 检查 390×844、414×896、768×1024：

- 可见按钮、链接、选择控件和整块选项的可操作热区不小于 44px；
- 页面无意外横向滚动；
- 菜单、遮罩、弹窗、联系方式气泡可通过点击、Esc 和返回焦点正常关闭；
- 访客进入受限页面后打开绑定弹窗，登录成功模拟路径能恢复目标页面；
- 反馈、复制、加载失败和重试状态具有明确可见结果；
- 课程表、会员、服务、反馈、广告详情和管理员页面在手机视口下首屏不出现控件重叠。
