# 支付密钥兼容迁移设计

## 目标

将支付密钥移出 Python 源码，同时不改变支付平台的商户号、下单参数、MD5 签名拼接规则或支付回调验签规则。

## 配置来源与优先级

支付密钥按以下顺序读取：

1. 环境变量 `PAY_SECRET_KEY`。
2. 本机私密文件 `data/payment_secrets.json` 中的 `pay_secret_key`。

私密文件必须被 Git 忽略，不得提交。运行时不再提供源码内置密钥回退，以防新密钥再次进入版本控制。

## 兼容与失败行为

现有部署可将当前支付平台提供的密钥写入私密文件后升级；下单签名与回调验签继续使用同一个已读取的密钥，因此不改变与支付平台的协议。

密钥未配置时，应用仍可启动；仅创建订单和处理支付回调会返回明确的支付配置错误，不会以空密钥继续签名或验签。

## 实现边界

- 在 `constants.py` 增加一个读取支付密钥的函数，并移除硬编码值。
- `routes/member_routes.py` 改为在请求时读取该函数的结果，并在使用前验证密钥存在。
- `.gitignore` 忽略 `data/payment_secrets.json`。
- 添加只覆盖密钥来源、优先级、缺失密钥行为的 Python 单元测试；不调用真实支付平台。

## 验收条件

- 源码不包含真实支付密钥。
- 环境变量优先于私密文件。
- 私密文件可作为不中断现有支付的迁移兜底。
- 有效密钥下生成的签名与迁移前使用同一密钥时完全一致。
- 缺失密钥不会发起支付请求或错误地接受支付回调。
