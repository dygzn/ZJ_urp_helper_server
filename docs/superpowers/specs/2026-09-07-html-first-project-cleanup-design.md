**范围：** `E:\URP\web` 当前工作树中的 Flask + 原生 JavaScript URP 教务助手

## 1. 目标

完成一次以真实页面入口为依据的项目功能收口，删除用户端和管理员端均无法使用、且没有已确认外部契约的孤立代码；修复模板和静态资源在运行进程或浏览器缓存下不及时更新的问题；把所有固定的用户可见文案和状态占位内容迁移到 HTML，使后续修改页面内容只需要编辑对应 HTML 文件，不需要同步修改 JavaScript。

本次不删除用户业务数据、不删除历史数据库表、不改变快捷指令 API 和支付回调等已确认需要保留的外部接口。

## 3. HTML 不生效问题的根因

当前代码存在两个相互独立的覆盖源：

1. 模板加载层：`app.py` 创建应用时没有开启 `TEMPLATES_AUTO_RELOAD`。通过导入 `app` 的常见 WSGI/开发启动方式观察到 `app.debug=False`、`app.jinja_env.auto_reload=False`、模板缓存容量为 400。HTML 页面路由也没有 `Cache-Control`，因此长生命周期进程可以继续使用旧的 Jinja 编译模板，浏览器也可以复用旧响应。
2. 浏览器运行层：`static/js/main.js` 的 `switchPage()` 用 JS 标题字典覆盖 `#page-title`；多个 `load*` 函数用硬编码字符串替换 HTML 中的加载、空数据、错误占位；`admin.js` 还会用硬编码模板重新生成统计、配置、公告、反馈和会员内容。这样即使服务器返回了新 HTML，页面启动或切页后也可能再次显示 JS 里的旧内容。

静态资源 URL 还使用固定 `?v=11` 版本号。修改 JS/CSS 后如果没有手动改版本号，浏览器仍可能使用旧资源。项目没有 Service Worker，问题来源是模板缓存、响应缓存和 JS 覆盖，而不是 Service Worker。

## 4. 设计

### 4.1 Flask 模板与资源缓存策略

在应用创建阶段明确设置 `TEMPLATES_AUTO_RELOAD=True`，保证长生命周期进程在模板文件变化后重新加载。增加统一响应处理：

- `/`、`/admin`、`/ad-detail` 返回 `Cache-Control: no-store, no-cache, must-revalidate, max-age=0`、`Pragma: no-cache` 和过期标记。
- `/static/*` 在当前无构建/指纹流程下也返回不可持久缓存的头，确保修改 JS/CSS 后刷新即可取得新资源。
- `app.run()` 使用环境变量解析出的 `debug` 值，不再无条件传入 `debug=True`。

模板中的资源引用去掉手工维护的固定版本号，或者统一使用由模板文件更新时间生成的资源版本；本次选择与 `no-store` 策略一致的无固定版本引用，避免“改文件但忘记改版本号”的再次发生。

### 4.2 HTML-first 文案契约

用户页和管理员页各自增加一个隐藏的 HTML 文案根节点，例如 `#user-ui-copy` 与 `#admin-ui-copy`。根节点中的元素用 `data-ui-copy="唯一键"` 标识；需要重复结构的状态和片段使用 `template[data-ui-template="唯一键"]`。所有固定用户可见内容，包括以下类别，必须从 HTML 节点读取：

- 加载中、空数据、网络失败、上游失败和访问受限提示。
- 页面标题、按钮状态、确认框按钮、复制成功/失败提示。
- 课程/考试/成绩/绩点/反馈/会员/提现/后台统计中的字段标签和状态标签。
- 管理员确认提示、操作结果、表格表头和空列表提示。

新增只包含逻辑的 `static/js/ui-copy.js`，不在其中保存任何中文文案。它提供按 key 读取文本和克隆 HTML template 的小型 API；`main.js`、`admin.js` 和广告详情脚本只调用该 API 并填充 API 返回的动态值。缺少 key 时返回空字符串或保留服务端返回的动态消息，不在 JS 中重新添加中文默认文案。

现有可直接编辑的页面标题、导航、说明、表单标签和静态卡片继续留在可见 HTML 中。`switchPage()` 从活动导航项读取标题，不再维护 JS 标题字典。访问门禁的结构预置在各页面的 HTML 中，JS 只切换 `hidden` 和页面锁定类，不再通过 `innerHTML` 重建门禁。

动态数据仍可由 JS 根据 API 响应生成；动态值不是静态内容。生成 HTML 时所有固定文本通过 `uiCopy(key)` 或 HTML template 注入，从而让“改文案”只需要编辑 HTML。

### 4.4 安全与数据边界

本次只做功能收口和页面渲染链路修复，不顺带修改密码存储、支付密钥、TLS 验证或数据库选型，避免扩大范围。删除接口不会删除历史表；如果历史 `pending_requests` 中存在记录，它们不再通过网站展示或处理，需要另行迁移/导出后再决定数据处置。

动态 API 内容继续进行 HTML 转义；文案根节点只包含项目维护者写入的可信静态 HTML，来自 API 的标题、正文、用户名、URL 和错误消息不能直接当作模板 HTML 插入。

## 5. 测试设计

实现前先加入并运行失败测试：

1. Flask 响应测试：三个 HTML 路由和静态资源都返回不可缓存头，模板自动重载配置为真，生产启动参数使用环境变量 debug 值。
2. HTML 文案契约测试：页面包含文案根节点；静态状态 template key 完整；`main.js`/`admin.js` 中不再出现被列入契约的中文静态字符串；页面标题来自 HTML 导航而非 JS 字典。
3. 死路由测试：应用 URL map 和源码不再注册删除清单；模板和前端不再引用删除的 endpoint、DOM ID 或 CSS 选择器。
4. 保留接口测试：快捷指令查询、支付回调、即时换绑和管理员有效标签页的现有测试继续通过。
5. 语法与回归测试：`node --check` 覆盖所有保留脚本；Python `unittest` 和现有 Node 测试全部运行。现有两个基线问题（脚本 URL 精确匹配和服务状态编码断言）必须一并修正或明确更新为当前行为。

## 6. 验收标准

- 修改 `templates/index.html`、`templates/admin.html` 或 `templates/ad_detail.html` 中的可见文案并刷新页面，内容能在不修改 JS、不重启长生命周期进程的情况下生效。
- 修改静态 JS/CSS 后刷新页面，浏览器不会继续使用固定版本号对应的旧资源。
- 删除清单中的路由请求返回 404，且源码、模板、脚本和 CSS 中不存在其运行时引用。
- 所有保留页面可从 HTML 导航或按钮到达；无页面入口的代码不再被注册。
- 动态 API 数据正常展示，用户输入和服务端返回内容仍转义，未引入新的 XSS。
- 历史数据库表和现有用户数据未被删除或重写。
- 全部自动化测试和语法检查有新鲜命令输出作为完成依据。
