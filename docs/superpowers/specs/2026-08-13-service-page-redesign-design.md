# “找我做事”页面改版设计

## 背景与目标

当前页面只展示管理员状态和两个账号，信息量过少，标题重复，联系方式看起来像普通数据行，访客无法快速判断“能获得什么帮助”以及“下一步应该做什么”。

本次改版目标是把该页面调整为面向本校同学的个人技术服务介绍页，在不脱离现有网站视觉体系的前提下，让访客能够快速了解服务范围、当前是否可咨询、合作流程和唯一联系入口。

页面定位为收费课程辅导与技术支持，不宣传或提供代写代做、代登录账号、保证分数或刷课服务。

## 设计依据

高转化服务页通常围绕单一行动组织内容，使用清晰的价值主张、可扫读的服务说明和醒目的联系入口。页面还需要尽量减少无关选择，让访客容易理解下一步。[Shopify 的落地页建议](https://www.shopify.com/blog/high-converting-landing-pages)强调可扫读内容、清晰导航信号与低摩擦路径；[Landingi 的服务页案例总结](https://landingi.com/landing-page/service-examples/)强调首屏价值说明、早期信任信息和聚焦的行动按钮。

本页不使用虚构评价、完成数量或案例来制造信任，而是通过明确服务边界、真实实时状态、透明流程和可先咨询的低门槛方式建立可信度。

## 视觉方向

- 延续原项目的浅灰页面背景、白色卡片、细边框、圆角和轻阴影。
- 继续使用现有蓝色 `var(--accent)` 作为唯一主要强调色，不采用独立的橙色或大面积暖色主题。
- 保留“亲切校园风”的语言风格，避免培训机构或技术外包公司的距离感。
- 内容最大宽度从当前 680px 放宽到 960px，使桌面端可以展示双栏首屏和四列服务卡；移动端恢复单列。
- 不引入照片、插画、外部字体或新的图片资源。

## 页面结构与最终文案

### 1. 首屏介绍

首屏左侧为主要价值说明：

- 小标题：`校园技术搭子`
- 主标题：`计算机课程遇到卡点？我来陪你解决。`
- 说明：`面向本校同学的编程辅导、项目指导与问题排查。把课程名称、具体要求和截止时间发来，我会先帮你免费评估，报价可以沟通。`
- 页面只保留一个主要操作按钮：`联系我`

首屏右侧为管理员实时状态卡，继续展示：

- 管理员设置的状态文字，例如“空闲”“上课中”“休息中”。
- 当前是否可以接新咨询。
- 最后更新时间。

状态数据继续来自现有 `/api/service-status`，后台编辑能力和数据结构不变。

### 2. 服务范围

标题：`这些问题都可以来问`

四张服务卡片：

1. `Python 编程`：`基础编程、数据处理、报错定位与代码讲解`
2. `Linux 实验`：`环境配置、命令使用、实验排错与思路辅导`
3. `云计算项目`：`需求拆解、部署流程、项目结构与问题排查`
4. `Excel 数据分析`：`数据清洗、公式分析、图表展示与结果说明`

卡片使用简单的文本或符号标识，不引入新的图片依赖。

### 3. 合作流程

标题：`合作很简单`

1. `把要求发来`：`附上课程、任务说明、截止时间和当前进度`
2. `免费评估`：`确认能否协助、处理方式、预计时间和报价`
3. `开始解决`：`按约定进行辅导、调试与成果讲解`

补充说明：`不知道能不能做也没关系，先把要求发来问一下。页面不会公开价格，以实际任务评估为准。`

页面不展示固定价格、起步价、虚构案例、评价、历史任务或完成数量。

## 联系方式交互

### 唯一入口

页面内只出现一个 `联系我` 按钮，不在首屏下方或页面底部重复放置QQ、微信按钮。

点击 `联系我` 后，在按钮上方打开轻量气泡。气泡包含两个选择：

1. `微信联系`
   - 展示说明：`复制微信号并尝试打开微信`
   - 微信号：`Dygzn123`
   - 点击时复用现有复制能力复制 `Dygzn123`。
   - 同时保留当前跳转地址：`weixin://contacts/profile/Dygzn123`。
2. `复制QQ号`
   - 展示QQ号：`786171937`
   - 点击后仅复制 `786171937`，不再使用 `tencent://` 跳转。

复制成功后，选项内显示短暂的“已复制”反馈；复制失败时保留可见账号，并在控制台记录警告。微信复制失败不应阻止协议跳转。

### 打开与关闭规则

- `联系我` 使用标准 `<button>`，通过 `aria-expanded` 表示气泡状态，通过 `aria-controls` 关联气泡。
- 再次点击 `联系我` 可关闭气泡。
- 点击气泡外区域或按 `Escape` 关闭气泡。
- 气泡默认隐藏，不占据页面布局空间。
- 气泡在窄屏中不得超出视口；保持按钮上方显示，并限制宽度为视口可用宽度。
- QQ选项使用 `<button>`；微信选项使用带自定义协议的 `<a>`。

## 数据流与组件边界

- `templates/index.html` 负责静态页面结构、最终文案、唯一联系按钮和气泡内的两个联系选项。
- `static/css/style.css` 负责白色主题布局、服务卡片、流程卡片、气泡、焦点状态和响应式布局。
- `static/js/main.js` 负责气泡的打开/关闭、点击外部关闭、Escape关闭、调用复制函数和短暂反馈。
- `static/js/service-status-ui.js` 继续负责状态视图模型和可测试的剪贴板复制，不改变 `copyText(text, environment?) -> Promise<boolean>` 接口。
- `/api/service-status`、管理员后台、数据库及状态数据模型保持不变。

## 响应式与可访问性

- 桌面端首屏为介绍卡与状态卡双栏；服务卡为四列；流程卡为三列。
- 移动端首屏、服务卡和流程卡按可读宽度折为单列或两列，主要操作保持容易点击。
- 可交互元素应有清晰的键盘焦点样式。
- 气泡使用可理解的文本标签，不只依赖颜色或图标传达含义。
- 状态颜色继续配合文本说明，不能只用绿色或灰色表示是否可咨询。

## 测试与验收

- 模板测试验证最终主标题、四类服务、三步流程和唯一 `联系我` 按钮。
- 模板测试验证页面不再出现独立的QQ/微信联系行。
- 模板测试验证QQ选项没有 `href`，且 `data-copy-text="786171937"` 正确。
- 模板测试验证微信选项保留 `href="weixin://contacts/profile/Dygzn123"` 和 `data-copy-text="Dygzn123"`。
- Node测试覆盖气泡打开、再次点击关闭、点击外部关闭和Escape关闭的纯状态逻辑。
- 现有复制函数测试继续验证 Clipboard API、兼容回退和失败分支。
- 运行完整 Python 与 Node 测试、JavaScript 语法检查和 `git diff --check`。
- 使用真实浏览器检查桌面与手机尺寸，确认气泡不溢出、状态仍能加载、QQ仅复制、微信仍执行协议跳转。

## 非目标

- 不新增案例、评价、历史任务或价格管理后台。
- 不新增表单、订单、支付、聊天或二维码功能。
- 不修改管理员状态接口和后台编辑页。
- 不承诺自定义微信协议能在所有浏览器或设备上正常唤起微信。
