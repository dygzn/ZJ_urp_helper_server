# “找我做事”联系方式超链接设计

## 目标

在现有“找我做事”页面中增加两个可点击的联系方式入口，让用户先验证 QQ、微信二维码解析链接在实际设备和浏览器中的跳转效果。

## 已确认链接

- QQ：`https://qm.qq.com/q/c9BOvFT6tc`
- 微信：`https://u.wechat.com/MMwBClCfxTYX-Z1rWS3_esc?s=2`

两个地址均从用户提供的个人二维码中解析得到。QQ 链接可进入腾讯 QQ 跳转流程；微信链接在普通浏览器中的最终行为由微信平台决定，本次不增加额外客户端唤起逻辑。

## 页面设计

在 `templates/index.html` 的“找我做事”页面中，于动态服务状态卡下方新增独立的联系方式区域：

- 显示“QQ 联系我”和“微信联系我”两个普通 HTTPS 超链接。
- 两个链接均在新标签页打开，并设置 `rel="noopener noreferrer"`。
- 链接保持简洁按钮样式，与现有状态卡的圆角、颜色和响应式布局协调。
- 手机窄屏下两个入口允许纵向排列，避免文字拥挤。

## 技术边界

- 不修改服务状态 API、数据库或管理员后台。
- 不引入 JavaScript 跳转判断、自定义 URL Scheme、二维码弹窗、复制账号或保存图片功能。
- 不把用户提供的二维码截图复制进仓库。
- 联系方式暂时直接写在前端模板中，便于快速验证；后续若需要后台修改，再单独设计配置能力。

## 错误与兼容行为

链接使用标准 `<a>` 元素，不拦截浏览器默认行为。若设备未安装对应客户端、平台拒绝唤起或微信仅显示官网，这是外部平台行为；当前页面不会误报“已打开”或自动重试。

## 测试

- 扩展首页模板测试，确认联系方式区域存在。
- 验证 QQ、微信链接的 `href` 与二维码解析结果完全一致。
- 验证两个链接使用新标签页和安全的 `rel` 属性。
- 运行现有 Python 与 Node 测试，确保服务状态加载和其他页面功能未受影响。

## 验收标准

用户进入“找我做事”页面后能看到两个联系入口；点击后浏览器使用对应 HTTPS 地址打开新页面。页面状态加载、可接单标识和更新时间展示保持不变。
