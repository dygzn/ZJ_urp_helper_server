# 问卷调查功能移除设计

## 背景与目标

项目不再需要站内问卷调查功能。需要完整移除用户端与管理员端入口、前后端实现、数据库结构及相关说明，并永久删除现有 `surveys` 表中的 1 条历史数据。

教务评教流程中来自 URP 系统的“没有可回答的问卷”提示不属于本站问卷功能，不在本次删除范围内。

## 选定方案

采用彻底移除方案：删除功能代码和文档，同时增加兼容旧部署的一次性清理逻辑。应用初始化数据库时执行 `DROP TABLE IF EXISTS surveys`，使已经存在的 SQLite 或 MySQL 数据库也能移除旧表。该操作不可恢复，用户已明确确认删除现有数据。

## 删除范围

### 用户端

- 删除导航栏“问卷调查”入口。
- 删除问卷页面容器和列表占位元素。
- 删除页面标题映射、页面切换分支、问卷列表加载与渲染逻辑。
- 从共用样式选择器中移除仅属于问卷页面的选择器，不影响公告、反馈等其他页面。

### 管理员端

- 删除“问卷管理”标签页、列表容器和新建按钮。
- 删除问卷新建/编辑弹窗及表单。
- 删除问卷列表加载、渲染、新建、编辑、提交和删除逻辑。
- 从共用样式选择器中移除问卷相关选择器，保留其他管理页面样式。

### 后端接口

- 删除管理员问卷列表、新建、编辑和删除接口。
- 删除用户问卷列表接口。
- 更新 `misc_routes` 的职责说明。
- 删除请求日志中问卷接口的名称映射。

移除后，下列路径不再注册，访问时应返回项目统一的 404 响应：

- `/api/surveys`
- `/api/admin/surveys`
- `/api/admin/surveys/<survey_id>`

### 数据库

- 从 SQLite 和 MySQL 初始化结构中删除 `surveys` 建表语句。
- 删除问卷索引和迁移字段配置。
- 添加旧表清理步骤，在数据库初始化时执行 `DROP TABLE IF EXISTS surveys`。
- 当前本地数据库的 `surveys` 表及其中 1 条数据会随清理步骤永久删除。

### 文档

- 更新 `AGENTS.md` 和 `CLAUDE.md` 中对问卷路由与数据表的描述。
- 不修改历史设计文档或 Git 历史。

## 验证策略

- 增加静态结构测试，确认用户端和管理员端不再包含问卷入口、页面、弹窗与脚本函数。
- 增加路由测试，确认问卷 API 不再注册并返回 404。
- 在临时数据库中执行初始化，确认不会创建 `surveys` 表，并能删除预先存在的旧表。
- 搜索全部受控源码，确认仅保留教务评教语境中的“问卷”文字，不存在本站问卷功能残留。
- 运行现有 Python 与前端 JavaScript 测试，确认公告、反馈、评教和其他功能不受影响。

## 风险与控制

- 数据删除不可恢复：范围限定为 `surveys` 表，且用户已明确确认删除其中现有数据。
- 共用 CSS 误删风险：只移除组合选择器中的问卷选择器，不删除其他选择器共享的声明块。
- 名称相似功能误删风险：保留 `urp/query.py` 中教务评教相关提示与处理逻辑。
