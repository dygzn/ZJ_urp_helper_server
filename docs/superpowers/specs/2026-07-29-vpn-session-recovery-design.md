# VPN 会话自动恢复与 Cookie 隔离设计

## 背景

项目通过安全网关访问 URP 教务系统。VPN 会话过期或服务器未开放时，安全网关仍可能返回 HTTP 200，但正文是“登录会话超时”“提示页面”或“网站维护”。现有 `vpn_session_alive()` 只检查状态码和是否为认证页，因此会把这些错误页误判为有效会话。

另一个问题是全局 `data/vpn_cookie.json` 当前会保存整个 `requests.Session` 的 Cookie。现场验证显示：

- VPN 认证和门户阶段只设置 `VSG_*` Cookie。
- 访问教务资源后才设置 `JSESSIONID`、`mapid` 和 `route`。

后面三类 Cookie 属于具体教务会话。把它们写入全局共享文件后，后登录用户可能覆盖先登录用户的会话，造成账号串话或业务数据不正确。

## 目标

1. VPN 模式可用时，成绩、课表、考试、评教等现有业务保持正常。
2. VPN 会话失效时，服务器自动重新登录 VPN，并把原业务请求重试一次。
3. 自动恢复成功时，用户无感知。
4. 自动恢复仍失败时，停止解析错误页面并返回清晰提示。
5. VPN 身份可以共享，但每个 URP 用户的教务会话必须隔离。
6. 不改变非 VPN 模式的请求行为。

## 非目标

- 不绕过 VPN 服务器的开放时间或外部维护状态。
- 不重构现有 Blueprint、业务服务或数据库结构。
- 不改变 URP 用户账号密码的存储方式。
- 不增加新的第三方依赖。

## 方案

采用“共享 VPN 身份、隔离 URP 用户会话”的方式。

### Cookie 边界

全局共享文件只允许保存名称以 `VSG_` 开头的 VPN Cookie。加载旧格式共享文件时也执行相同过滤，因此历史文件中的 `JSESSIONID`、`mapid` 和 `route` 不会再进入新会话。下一次保存时，旧文件会自然收敛为仅含 VPN Cookie 的格式。

用户目录中的 `user_data/{account}/cookie.json` 继续保存该用户完成 URP 登录后的全部 Cookie。创建查询会话时，先加载用户 Cookie，再用最新的共享 `VSG_*` Cookie 更新 VPN 身份；共享 Cookie 不得覆盖用户的 URP 会话 Cookie。

### 页面分类

在 `urp/login.py` 中集中判断响应类型：

- VPN 认证页：URL 或正文包含现有认证页特征。
- VPN 错误页：安全网关错误路由、`pageName: "error"`、`var errmsg`、会话超时或维护页特征。
- URP 登录页：存在 `loginForm` 且表单指向 `loginAction.do`。
- URP 已登录首页：存在明确的 `menu/top.jsp`、`menu/mainFrame.jsp` 或现有教务面板特征。

`vpn_session_alive()` 仅在响应为预期的 URP 登录页或已登录首页时返回真。状态码 200 不再单独代表会话有效。

`_looks_logged_in()` 同样改用明确的 URP 已登录标志，并优先排除 VPN 认证页、VPN 错误页和 URP 登录页，防止把任意非登录页面当成成功。

### 自动恢复

`urp/login.py` 提供统一的 VPN 恢复入口：

1. 获取现有 `_VPN_LOCK`，防止并发请求同时重复登录 VPN。
2. 锁内再次检查最新共享 VPN 会话，避免等待期间其他请求已经完成恢复。
3. 会话仍无效时清除共享 VPN Cookie，并使用现有 VPN 凭据重新认证。
4. 验证新会话确实能访问 URP 登录页或已登录首页。
5. 只保存新的 `VSG_*` Cookie。

`urp/query.py` 增加统一请求包装器，所有成绩、课表、考试和评教请求通过该包装器发送。收到正常 URP 响应时直接返回；收到 VPN 认证页或错误页时调用恢复入口，将新的共享 `VSG_*` Cookie 更新到当前用户查询会话，然后原样重试请求一次。

重试次数固定为一次，避免外部 VPN 不可用时形成循环登录或请求风暴。非 VPN URL 不执行该恢复逻辑。

### 错误处理

定义明确的 VPN 不可用异常。以下情况触发异常：

- VPN 重新认证失败。
- 重新认证后仍无法到达预期 URP 页面。
- 原业务请求重试后仍返回 VPN 认证页或错误页。

异常消息使用中文，说明系统已经自动重连但未成功，并建议稍后重试。现有路由层会把异常转换为 `success: false` 响应，因此错误页不会再被成绩、课表或考试解析器当成空数据。

诊断信息可以保留响应类型、URL 和状态码，但不得记录账号密码、认证正文或 Cookie 值。

## 代码范围

- 修改 `urp/login.py`
  - 过滤共享 Cookie。
  - 分类 VPN/URP 页面。
  - 修正存活与登录成功判断。
  - 提供带锁的 VPN 自动恢复入口。
- 修改 `urp/query.py`
  - 增加单次恢复与重试的统一请求包装器。
  - 将现有查询请求切换到包装器。
- 新增 `tests/test_vpn_session_recovery.py`
  - 使用标准库 `unittest`，不引入测试依赖。

不修改用户已有的 `urp/query.py` 绩点解析改动；实现时只在请求发送位置做最小范围调整。

## 测试

回归测试至少覆盖：

1. 从旧共享文件加载 Cookie 时只返回 `VSG_*`。
2. 保存共享 Cookie 时不写入 `JSESSIONID`、`mapid` 或 `route`。
3. HTTP 200 的 VPN 会话超时页被判断为无效。
4. HTTP 200 的 VPN 维护页被判断为无效。
5. URP 登录页被判断为有效 VPN 通道。
6. URP 已登录首页被判断为有效 VPN 通道和成功登录。
7. 查询首次收到 VPN 错误页时执行一次恢复，并重试成功。
8. 恢复失败或重试仍为错误页时抛出用户可理解的异常。
9. 非 VPN 模式不会触发 VPN 恢复。

测试使用内存响应和临时 Cookie 文件，不访问真实 VPN，不改动 `data/`、`user_data/` 或 SQLite 数据库。

## 验收标准

- 所有新增回归测试通过。
- Python 源码编译检查通过。
- Flask 应用可导入并保持现有路由注册完整。
- 现有工作区的其他修改未被覆盖。
- VPN 会话失效时最多自动登录一次、业务请求最多自动重试一次。
- VPN 恢复成功后业务返回正常数据；恢复失败时返回明确错误而非空业务结果。
