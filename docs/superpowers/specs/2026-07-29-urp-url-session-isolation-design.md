# URP URL 切换会话隔离设计

日期：2026-07-29

## 背景与问题

系统允许管理员在多个 URP 地址之间切换。当前实现把“当前 URL”当成进程级动态配置，但用户 Cookie 和登录缓存只按用户名保存，因此切换时存在四类问题：

1. 同一个 HTTP 请求内可能先在 URL1 校验登录，随后读取到已经切换的 URL2 发起业务查询，导致校验目标和查询目标不一致。
2. `user_data/{username}/cookie.json` 被所有 URL 共用，URL1 与 URL2 的教务 Cookie 会相互覆盖或被错误复用。
3. `_login_cache` 只按用户名缓存，URL1 的有效缓存可能让 URL2 跳过真实登录检查。
4. 配置文件直接覆盖写入，并发读取可能短暂读到不完整 JSON，进而落入默认配置。

此外，部分在线评教接口只有会员校验，没有在访问 URP 前执行自动登录恢复，URL 切换后更容易直接使用无效会话。

## 目标与成功标准

- 切换前已经开始的请求继续使用其进入请求时的 URL，正常完成。
- 切换完成后新进入的请求统一使用新 URL。
- 同一用户在不同 URL 上使用相互隔离的教务 Cookie；切回旧 URL 时优先复用旧 URL 的有效 Cookie。
- 新 URL 的教务 Cookie 缺失或失效时自动尝试登录；同一用户、同一 URL 的并发请求只执行一次真实登录。
- VPN 网关仍然使用一个全局共享会话。切换 URL 不触发 VPN 登录，也不为用户或 URL 创建 VPN 会话副本。
- 只有确认全局 VPN 会话失效时，才在全局锁内尝试一次恢复；其他并发请求等待并复用恢复结果。
- 登录恢复仍失败时返回清晰错误，不自动回退到旧 URL，避免管理员切换意图被悄悄绕过。
- 不改变设备绑定、会员、数据库结构和现有 API 响应协议。

## 设计

### 1. 请求级 URL 快照

`get_current_urp_url()` 在 Flask 请求上下文中第一次调用时读取当前配置，并将标准化后的 URL 保存到 `flask.g`。同一个请求中的后续调用只返回该快照，不再读取全局当前索引。

没有 Flask 请求上下文的后台任务，在一次业务操作开始时读取一次 URL，并将该值作为局部变量向下传递。`URP_login`、`URP_query` 及登录检查应接收或捕获这个明确的 URL，避免一次操作中再次解析可变配置。

URL 标准化至少统一末尾斜杠，保证同一地址不会因为书写差异产生两个会话标识。

### 2. 按用户、按 URL 隔离教务 Cookie

使用标准化 URL 的 SHA-256 摘要作为稳定标识，不使用数组索引，因为管理员可能调整 URL 顺序。Cookie 路径为：

```text
user_data/{username}/cookies/{url_fingerprint}.json
```

每个文件只保存该用户在对应 URP 地址上的应用 Cookie。名称以 `VSG_` 开头的 VPN Cookie 不得写入用户 Cookie 文件。

旧版 `user_data/{username}/cookie.json` 保留用于平滑迁移：

1. 当目标 URL 尚无独立 Cookie 文件时，旧文件只作为一次迁移候选。
2. 过滤其中的 `VSG_*` Cookie，并在目标 URL 上实际验证。
3. 验证成功后写入目标 URL 的独立文件；验证失败则走正常自动登录。
4. 暂不删除旧文件，以便回滚；一旦目标 URL 已有独立文件，不再用旧文件覆盖它。

### 3. URL 感知的登录缓存与并发控制

登录缓存键改为 `(username, url_fingerprint)`，缓存命中只能跳过同一 URL 的重复校验，不能跨 URL 复用。现有直接操作 `_login_cache` 的装饰器改用统一的缓存失效函数，支持失效指定 URL 或该用户的全部 URL。

为自动教务登录建立按 `(username, url_fingerprint)` 分组的锁：

1. 请求发现 Cookie 缺失或失效后获取该锁。
2. 获取锁后再次检查 Cookie 与缓存，防止前一个请求已经完成恢复。
3. 仍无效时才执行验证码识别和教务登录。
4. 成功后写入该 URL 的 Cookie 文件并更新对应缓存；失败则所有等待请求得到一致、明确的错误。

该锁只控制用户的教务登录，不替代 VPN 全局锁。

### 4. VPN 保持全局单会话

现有 `data/vpn_cookie.json`、`_VPN_LOCK` 和保活机制继续作为唯一 VPN 会话来源：

- 文件中只保存 `VSG_*` Cookie。
- 访问 VPN URL 时，把全局 VPN Cookie 合并到当前请求的 Session；访问直连 URL 时不合并。
- 管理员切换 URL 时不清空、不刷新、不重新认证 VPN。
- 普通业务请求不得因为“目标 URL 的用户教务 Cookie 不存在”就触发 VPN 密码认证。
- 只有 `vpn_session_alive()` 或等价的明确失效判断失败时才进入 `recover_vpn_session()`。
- `recover_vpn_session()` 在 `_VPN_LOCK` 内重新加载共享 Cookie 并二次检查；若其他请求已经恢复则直接复用，否则只执行一次 `_vpn_password_auth()`。

因此，首次切到 URL2 可能需要该用户进行一次教务系统登录，但只要全局 VPN 会话仍有效，就不会重新登录 VPN。

### 5. 配置读写一致性

配置更新使用进程内可重入锁，并采用“同目录临时文件写完后 `os.replace`”的原子替换方式：

- 锁避免同一进程内多个管理员更新相互覆盖。
- 原子替换确保并发读取者只能看到旧版或新版完整 JSON，不能看到半写入文件。
- URL 切换成功后只影响尚未创建 URL 快照的新请求。

### 6. 所有在线 URP 功能统一执行登录恢复

所有实时访问 URP 的路由必须在查询前针对同一个 URL 快照完成登录检查。成绩、课表更新、考试更新等现有入口继续沿用登录装饰器；在线评教相关接口改用同时包含会员校验和登录恢复的装饰器。

只读取本地缓存的课表、考试等接口不强制访问 URP，也不因为 URL 切换阻塞用户。

## 错误处理

- 用户教务登录失效：先在对应 URL 上自动登录一次；仍失败时返回现有登录失败/会话失效语义。
- VPN 会话失效：由全局恢复流程尝试一次；仍失败时返回 VPN 暂不可用的明确提示。
- 目标 URL 网络不可达：返回该 URL 的连接错误，不静默切回 URL1。
- 配置内容无效：拒绝切换并保留上一份有效配置。

日志应包含脱敏后的 URL 标识、用户和恢复阶段，不能记录密码、完整 Cookie 或 VPN 凭据。

## 验证方案

新增自动化回归测试覆盖：

1. 同一请求中管理员切换配置后，登录检查和业务查询仍使用同一 URL 快照。
2. URL1、URL2 为同一用户生成不同 Cookie 文件；URL 顺序调整不改变文件映射。
3. 用户 Cookie 文件不包含 `VSG_*`，共享 VPN 文件只包含 `VSG_*`。
4. URL1 的登录缓存不能让 URL2 跳过验证。
5. 同一用户并发访问 URL2 时只发生一次真实教务登录。
6. URL1 → URL2 → URL1 后分别加载正确 Cookie，有效会话不重复登录。
7. 旧 `cookie.json` 可成功迁移；无效旧 Cookie 会自动登录且不污染其他 URL。
8. 全局 VPN 会话有效时，多用户访问和多次 URL 切换均不会调用 VPN 密码认证。
9. 全局 VPN 会话失效时，并发恢复只调用一次 VPN 密码认证，其他请求复用结果。
10. 配置并发读写始终得到完整 JSON，不回落到意外的默认 URL。
11. 在线评教接口在会员校验后执行同 URL 的登录恢复。
12. 现有登录、成绩、课表、考试、评教和 VPN 恢复回归测试全部通过。

## 非目标

- 不在管理员切换时主动为所有在线用户预登录新 URL。
- 不实现 URL 故障时的自动回退或负载均衡。
- 不修改用户绑定、会员、支付或数据库表结构。
- 不新增第三方依赖。
