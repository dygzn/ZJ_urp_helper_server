# Favicon 与 HTTP 错误处理修复设计

## 背景

浏览器会自动请求 `/favicon.ico`。项目当前没有该文件或路由，因此 Flask 先产生正常的 404；但 `app.py` 注册了覆盖所有异常的处理器，非 API 异常会被重新抛出，导致这个 404 再次进入异常处理并最终变成 500。相同问题也会影响其他不存在的网页地址；不存在的 API 地址则会被错误包装成 500。

## 目标

- `/favicon.ico` 请求不再产生异常日志或 500。
- 不存在的普通网页正确返回 404。
- 不存在的 API 正确返回 JSON 和原始 HTTP 状态码。
- 真正的 API 程序异常继续返回现有 JSON 500 格式。
- 不修改登录、VPN、课表、数据库或其他业务逻辑。

## 方案

1. 在 Flask 应用中注册 `/favicon.ico` 路由，返回空响应和 HTTP 204。当前项目没有可复用的品牌图标，因此不新增临时图案或二进制资源。
2. 在全局异常处理器中先识别 Werkzeug `HTTPException`：
   - `/api/` 路径返回 `{'success': False, 'message': error.description}`，状态码使用异常自身的 `code`。
   - 非 API 路径直接返回原始 HTTP 异常，让 Flask 保留 404 等标准状态。
3. 非 HTTP 的 API 异常继续返回现有 `服务器内部错误` JSON 和 500。
4. 非 API 的非 HTTP 异常保持现有抛出行为，本次不扩大到网页 500 页面设计。

## 数据流

- 浏览器请求 `/favicon.ico` → 命中显式路由 → 返回 204。
- 请求不存在的网页 → Flask 产生 `NotFound` → 全局处理器识别为 HTTP 异常 → 返回标准 404。
- 请求不存在的 API → Flask 产生 `NotFound` → 全局处理器返回 JSON 404。
- API 业务代码抛出普通异常 → 全局处理器返回现有 JSON 500。

## 测试

新增 Flask 测试覆盖：

- `/favicon.ico` 返回 204。
- 任意不存在的网页返回 404，不抛异常且不返回 500。
- 任意不存在的 API 返回 JSON 404。
- 人工测试 API 普通异常仍返回 JSON 500。
- 首页和现有完整回归测试继续通过。
